## 小説風リプレイ用プロンプト（コピペ用）

> ココフォリアのログを小説風のリプレイHTMLにするプロンプトです。右上の「コピー」で全文を写し、コードを実行できるAI（Claude・ChatGPTなど）に、ログと立ち絵・背景画像と一緒に貼って送ってください。

````
# TRPGセッションログ → 小説版リプレイHTML

これから渡すTRPGのセッションログ（ココフォリアのHTML書き出しなど）と、立ち絵・背景・タイトル画像を使って、誰でもブラウザで読める小説風のリプレイページを作ってください。コード実行機能（Python）を使って作業し、最後に完成したHTMLファイルをダウンロードできる形で渡してください。

この手順はAIによっては挙動を試していません。環境の違いで動かない部分は、目的から外れない範囲で調整してください。ただし「2. 小説化のルール」は守ってください。調整した箇所があれば、最後に短く教えてください。

## 0. 最初に確認すること
- 探索者（PC）とKPCが誰か、ログの発言者名から判断できない場合だけ、選択肢で聞く

## 1. ログを読む
ココフォリアのログは次の形式です。

```
<p style="color:#xxxxxx;"><span> [タブ名]</span><span>発言者</span> : <span>本文<br>…</span></p>
```

次のスクリプトで「[タブ]発言者: 本文」の1行テキストにして、最初から最後まで読む。

```python
import re, html
LOG = 'ログファイルのパス'
s = open(LOG, encoding='utf-8').read()
pat = r'<p style="color:(#[0-9a-fA-F]+);">\s*<span>\s*\[(.*?)\]</span>\s*<span>(.*?)</span>\s*:\s*<span>(.*?)</span>\s*</p>'
for m in re.finditer(pat, s, re.S):
    t = html.unescape(re.sub(r'<br>', '／', m.group(4))).strip()
    print(f'[{m.group(2)}]{m.group(3).strip()}: {t}')
```

- 出力が長い場合はテキストファイルに書き出し、分割して末尾まで必ず確認する（成長処理やSAN回復は最後にある）
- ココフォリア以外のログは、形式に合わせて抜き出し方を変える

### 読み分け
- 本文に使う：PC・KPC・NPCのセリフと行動、KPの場面描写
- 本文に使わない：KPのルール説明や操作説明、OOCの雑談
- ダイス：`CCB<=50 【聞き耳】 (1D100<=50) ＞ 4 ＞ 決定的成功/スペシャル` から、技能名・目標値・出目・結果を拾う。`system: [ 名前 ] HP : 12 → 11` はHPの変化として拾う
- KPCのコマで書かれた動作や表情の描写は、地の文として使う

## 2. 小説化のルール（必ず守る）
- 三人称で、PC寄りの視点で書く。章はログの流れに沿って分ける（導入／探索／各場面／エンディング）
- セリフはログのまま使う。言い回しを変えたり、句読点を足したりしない
- ログにない人物設定を作らない。職業の詳細、性格、経歴、「慣れている」といった決めつけは書かない。卓中に確定した情報は使ってよいが、そこから膨らませない
- 場面の補足（動作や間合い）は最小限にする。人物の内面や過去を足さない
- PLのOOCでも、キャラの心の声として成り立つものは心の声として使ってよい
- ダイスの結果を描写に反映する（成功なら上手くいく、失敗なら上手くいかない、決定的成功は鮮やかに）。ただし結果を誇張して設定を作らない
- ルールと違う裁定があった場合は、本文はそのまま残し、ダイスのカードの下に「ルール補足」を簡潔に付ける（通常ルールでの扱い、ファンブルかどうか、この卓の独自裁定として扱うこと）。HPなどの結果は巻き戻さない
- 成長処理とSAN回復は最後の「通知表」にまとめる。最終値はKPが確定させた数値に合わせる
- 数値・技能値・固有名詞はログにあるものだけを使う。不明なところは空欄にするか確認する

## 3. ページの構成
- 表紙：タイトル画像があれば使う（h1は視覚的に隠して残す）。なければ文字の見出し。下にシステム名、PC名・KPC名、ダイス結果の凡例、元ログのダウンロードボタン
- 目次：各章へのリンク
- 登場人物：立ち絵のカードと、表情差分の丸アイコン
- 本文：章ごとに見出しを付ける。場所に合う背景画像があれば、見出しの下に横長のバナーとして入れる
- セリフ：顔アイコン付きの吹き出し。PCは左、KPCは右。場面に合わせてセリフごとに表情差分を選ぶ。NPCは名前付きの引用ブロック、心の声はグレーの地の文
- ダイスのカード：出目、技能名、目標値、結果を表示。決定的成功＝金で★付き、成功＝緑、失敗＝赤、ダメージ・HP変化＝紫。得点がある場合は右端に点数
- エンディング：PCとKPCの立ち絵を並べた一枚、END名、SAN回復のカード
- 通知表：技能、成長の内訳、最終値の表
- フッター：ダウンロードボタンをもう一つ
- デザイン：本文は明朝（Shippori Mincho）、UIはゴシック（Zen Kaku Gothic New）。ライト／ダーク両対応、スマホでは1カラム

### 元ログのダウンロードボタン
元ログのHTMLをbase64にして `<script id="rawlog" type="text/plain">` に埋め込み、クリックでBlobを作って `a.download` で保存させる。ファイル名は英数字にする（例：`scenario_ccfolia_log.html`）。失敗した場合は画面に短いメッセージを出す。

## 4. 画像の処理
- 立ち絵：幅560px程度のwebp
- 顔アイコン：顔まわりを正方形に切り抜いて240pxのwebp（透過は保つ）。切り抜いたら一覧画像を作って目で確認する
- 背景・タイトル：幅1200〜1400pxのwebp（品質80前後）
- 使わない画像はHTMLに入れない

## 5. 確認
- ダイスの出目・結果、HP、成長値がログと一致しているか照合する
- 画像がすべてHTMLに埋め込まれ、外部ファイルへの参照が残っていないか確認する
- ダウンロードボタンのデータを復元し、元ログと同じ内容になるか確認する

## 6. 納品
- 画像はすべてdata URIで埋め込み、1ファイルで完結するHTMLにする（Google Fontsの読み込みはそのままでよい）
- 完成したHTMLをダウンロードできる形で渡す。ファイル名は短い英数字
- 公開方法を一言添える：ファイルを送ればそのまま読める／GitHub Pagesに置く場合は、リポジトリにアップロードすれば `https://<ユーザー名>.github.io/<リポジトリ名>/<ファイル名>.html` で公開される
- 画像が多くファイルが重くなりそうな場合は、画質を下げてよいか先に確認する

## 7. 返答
- できたものと、ログから判断した点（独自裁定、矛盾、表情の割り当てなど）を短く伝える
- 判断が必要なところは選択肢で聞く
````
